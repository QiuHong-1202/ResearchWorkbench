# 审稿工作区规则

审稿任务从当前项目启动。仓库外工作区只保存稿件与成果；通用规则、模板和工具由本技能保存，不写入稿件工作区。

## Workspace resolution

- 开始任何审稿任务前，运行 `uv run --no-sync python "<SKILL_ROOT>/scripts/workspace.py"`，读取技能根目录的 `workspace.local.json` 的 `REVIEW_WORKSPACE`。路径必须是当前系统可访问的绝对目录；未配置或不存在时提示配置，不自动创建另一个审稿根目录。
- 不硬编码用户名、云盘安装位置或 Windows 盘符。跨机器链接使用稿件目录内的相对路径，脚本使用 pathlib；文本使用 UTF-8。
- 仓库外文件不会自动继承本文件，主 Agent 必须将这些规则和解析出的稿件路径明确传递给处理审稿任务的子任务。

## Submission layout

```text
<REVIEW_WORKSPACE>/<year>-<venue>-<paper-id>/
  submission/     # 原始论文、补充材料、视频和作者回复
  artifacts/      # 提取全文、翻译、图片、阅读笔记等保留成果
  related/        # 用户下载的重要相关工作
  review-form/    # 本次审稿表单、邀请和具体要求
  review.md       # 工作笔记和审稿草稿
  final/          # 用户确认实际提交的版本
```

- 保留原始文件名；年份和编号以已知信息为准，信息不明时沿用目录名称并注明，不擅自推断。
- 新稿件使用以上结构；历史目录逐步整理，先检查已有文件与链接，不批量重命名历史资料。
- review-workspace 的整理及准备模式在新建或复用稿件目录时初始化缺失的 related/，已有内容保留；相关论文不默认纳入投稿正文及补充材料的准备流程。
- 新建 review.md 使用技能内的 [空白模板](../assets/review.md)；保留用户已有草稿。final/ 中的已提交版本不覆盖，修订另存版本。
- 调用 paper-extract、paper-note、paper-translate、formula-fix 或 markdown-fix 时，先读取相关技能。审稿任务的记录目录显式指定为稿件 artifacts/ 下的目录，提取使用显式 --input 和 --out-dir；笔记、翻译和元数据写回该记录目录。本审稿工作流取代技能中的默认 library/ 输出位置，不将保密稿件导入 library/ 或公共索引。
- 先复用当前稿件已有全文，再考虑重新提取；查阅其他文献时先检查当前项目的 library/。
- 一次性脚本、日志、截图及诊断文件放在当前项目的 .agent-tmp/<task-id>/；保留成果放在稿件目录的 artifacts/，不修改项目管理的缓存位置。

## Review and file safety

- 阅读技能内的 [通用审稿原则](general.md) 以及稿件 review-form/ 中的本次要求。具体审稿要求优先于通用模板；非公开的表单和要求只留在仓库外工作区。
- 原文、作者信息、评分、审稿草稿、翻译、笔记和提交版本不进入 Git。仓库只保留通用规则、空白模板、工具以及公开指南的来源链接和必要摘要。
- 合并文件时先比较内容；同内容复用，冲突保留双方并报告，不自动覆盖。迁移后核对文件完整性和相对链接。
- 删除未跟踪、忽略或仓库外文件前列出路径、提醒用户并等待明确确认；当前任务创建的可丢弃测试文件除外。不得自行提交、推送或修改 Git 索引。
- 不自动提交审稿。final/ 仅保存用户明确确认已提交或要求归档的版本。
