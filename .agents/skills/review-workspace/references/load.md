# 加载审稿上下文

默认只读；用户同时提出具体审稿问题时，在完成加载后继续回答。共用定位与审稿规则由技能入口处理。

## 加载已有上下文

- 读取目标 `review.md`。本次要求为 PDF 或 Word 表单时使用可用的读取工具；无法读取时注明实际缺失范围。沿用当前会话已明确的授权，不重复请求相同确认。
- 盘点 `submission/`、`artifacts/`、`related/`、`final/`，区分正文、补充材料、作者回复、相关工作、工作草稿与归档版本。`related/` 中的论文先列为参考材料，按当前问题或用户指定范围读取，不混入投稿正文；历史目录缺少 related/ 时保持只读，不补建。历史 `review.md` 可能只是索引：沿相关链接读取已有意见；多个不同审稿轮次或正文版本无法确定时先确认，不按文件名或时间判定最终提交版本。
- 按本技能的 [产物约定](artifacts.md) 定位已有记录，先读 `paper.json` 的正文、译文和 `supplements` 关联，以及 `assets/review-prepare.json` 的阶段状态。新记录通常在 `artifacts/paper/`；历史目录或译文名原位兼容。按字段基准解析路径，manifest 的图片路径相对 `output_dir`，不统一套用 manifest 目录；旧路径在选定稿件内核对，不执行历史 prompt。
- 默认完整阅读主论文已有原文 `fulltext.md`，长文分段读取，避免工具输出截断造成遗漏。中文译文用于用户指定的中文阅读或对照；仅有译文时可先加载并说明缺少原文。补充材料、作者回复和历史意见先建立材料清单，按当前问题或用户指定范围读取；不将“发现文件”写成“已阅读全文”。用户明确要求加载全部材料时，依次阅读可读文本，并注明未观看的视频或未检查的图像。
- 正文尚未提取时，可直接读取源 PDF 以满足当前问题；无法完整读取则说明实际范围及缺失内容。只加载不自动启动提取、修复或翻译，可提示使用 `$review-workspace 准备 <稿件目录名>` 补齐材料。
- 从阶段报告及 manifest 读取影响阅读的警告，例如缺页、公式歧义或页码映射限制；已有准备摘要可用作导航，缺少摘要、翻译 QA 报告或新模型字段不阻止加载。默认不读任务 prompt、完整 pages.json 或 Marker 元数据。历史阶段状态表述为“记录显示”；需要确认译文对应当前全文时核对哈希，有差异则报告。准备与审稿状态分别表述，提交状态以用户确认及已有版本为依据。

## 返回与后续使用

简洁告知选定稿件的编号、标题、目录状态、实际阅读范围、可用译文及补充材料，以及影响继续审稿的缺失项或警告。提供正文、中文译文和工作草稿中实际存在文件的可点击绝对路径链接；不把正文复制到仓库，也不额外生成加载报告。

在当前对话中保持选定稿件及其文件位置，后续问题优先引用原文章节、公式、图表和可核实的 PDF 页码；未经核对的提取页码不能当作 PDF 页码。切换稿件时重新定位和加载，避免沿用上一稿件的要求或判断。仅加载时不写出评分或新的审稿结论，也不承诺跨聊天永久保留上下文。
